# RoomLink Database Schema

**PostgreSQL · database `rmdb` · schema `public`**

Multi-tenant schema for a digital intercom & guest-service platform. Every operational table hangs off `hotels` by `hotel_id` and cascades on delete; platform-level rows (Super Admin, system roles) simply leave that column null. Primary keys are UUIDs generated by `pgcrypto`, state is modelled with Postgres enums, and flexible per-tenant data lives in `jsonb`.

## 13 · Dashboard Views
*2 views*

### v_platform_kpis

One-row snapshot for the Super Admin dashboard — each column is an independent scalar subquery.

- `total_hotels`, `active_hotels`, `trial_hotels`, `onboarding_hotels` — counts from `hotels` by `status`
- `total_rooms` — count from `rooms`
- `open_support_tickets` — `support_tickets` where status not in (resolved, closed)
- `failed_payments` — `payments` where status = failed

### v_hotel_onboarding_progress

Per-hotel completion percentage, grouped from `onboarding_tracker`.

- `hotel_id`
- `percent_complete` — steps with status = complete ÷ total steps × 100, per `hotel_id`
